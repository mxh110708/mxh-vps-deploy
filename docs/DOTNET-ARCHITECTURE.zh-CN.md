# C# 桌面重构与平台边界

v0.9.1 采用 WinUI 3 Windows 界面、现代 .NET 共享运维核心与系统适配层。此文件描述实现结构与边界；发行不代表已经安装或连接生产。此前 WPF v0.7.0 的发行已撤销，源提交保留。

## 依赖方向

`Desktop → Windows → Infrastructure → Core`。Core 是 `net10.0`，不得引用 Windows API、WinUI、WPF、PowerShell 或安装程序。Infrastructure 是跨平台的 SSH/SFTP、文件与 HTTP 实现，不依赖 Windows 层。Windows 层独立实现用户凭据保护、必要私钥权限、文件选择和安装更新。Desktop 只负责呈现、表单、审阅及用户决策，不拼接远端命令或直接写生产文件。

共享核心的任务模型、计划、验证、状态机、恢复范围、归档格式与任务记录由三个系统共用。以后新增 macOS/Linux 界面与系统适配项目，不复制核心。只为 Windows 提供安装包；跨平台编译及测试不能宣称已提供 Mac/Linux 桌面应用。

## 行为边界

- 选实例、填表、保存草稿、导航与启动应用不连接 VPS。执行使用已审阅计划的指纹；输入修改会使审阅失效。
- 主机密钥必须经用户核对指纹后信任。密码不放入命令行、环境变量、任务历史或公开日志。
- 私人数据统一在应用 `private`，不读取命令行外部根偏好、不自动搬迁旧归档、不增加旧归档导入界面。
- 普通归档沿用用户权限；仅受管 SSH 私钥可执行必要权限处理，绝不修改提供商源密钥。
- 任务结果分别表示完成、取消、失败、待恢复、用户跳过；取消采用安全边界，不能把进程退出当成远端已经回滚。
- 操作按组件限定。协议恢复不能覆盖 Komari；仅主控恢复不能触 Tunnel；旧计划不能直接覆盖后加的独立网络调优或 ATT 增量。
- 应用更新只处理受管清单，保留私人归档、local.json 和未受管文件；遇到本地改动、冲突、链接或未知布局拒绝覆盖。
- 卸载明确选择保留或彻底删除私人数据；删除只限选定应用目录，拒绝跟随链接。首次打开不自动迁移归档或生产状态。

## 验证

共享项目开启平台兼容分析，CA1416 作为错误。跨平台测试覆盖路径隔离、指纹过期、任务并发/取消/恢复、秘密脱敏、SSH 主机信任和受限恢复范围。Windows 项目单独验证 WinUI 窗口和安装更新生命周期。所有本地验证使用隔离夹具，不连接生产、不改权威、不切代理/TUN。
