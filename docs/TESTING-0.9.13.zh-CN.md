# v0.9.13 IPv6、证书与恢复补测

2026 年 10 月 10–11 日，在用户重装并授权的双栈专用测试机上完成空白 Debian 13 amd64 部署及后续维护。使用 [B 方案应用内接口](BACKGROUND-TESTING.zh-CN.md)驱动真实 WinUI 表单、审阅、凭据提示和任务协调器。测试材料保存在隔离私人目录，固定核对用户本次接纳的 SSH 身份，没有用旧归档替代首次部署。

本机没有直连 IPv6 路由。用户允许通过已有 VPS 的只读中转实测真实 IPv6 SSH、HTTPS 和出口；应用内无法完成的直连项仍记录为 `SkippedByUser`，整体验收保留 `Incomplete`，没有改成通过。非测试 VPS、原始归档、系统代理和 TUN 未修改；后台窗口激活及前台采样均为零。

## 实测发现与修正

- **证书 DNS API 的出口不一致。** 双栈主机的默认 IPv6 源地址可能不是 Token 允许的地址。实测默认源被拒绝，指定已允许的 IPv4 或主 IPv6 后区域查询成功。预检依次尝试 IPv4、IPv6，取得实际成功源地址；受管 Certbot 包装程序仅对 Cloudflare DNS API 固定该地址族和源地址，申请、续期及自动计时器共用。其他网络请求保持正常路由，包装程序纳入备份、范围恢复与退役清理。
- **自动回滚后计时器仍活动。** 一次真实会话中断后，监控组件已撤回，但旧计时器残留，阻止下一次备份。新回滚程序完成事务后停用计时器；恢复已完成事务时，只有服务单元明确指向同一已回滚备份且没有运行中的回滚服务，才清理残留。未知所有者或冲突仍拒绝，没有重新执行恢复。
- **备份尚未建立却卡在恢复状态。** 本地已记录 `Arming`，远端可能在取得所有者前失败。增加持远端锁的无所有者核验；只有没有远端备份、任务身份、所有者和活动回滚任务时，才关闭本地未建立事务。不会释放其他任务、重放安装或覆盖计划。
- **主控启动核对和失败原因。** 新主控使用 `Type=exec`，等待程序真正执行后再核对进程，并单独验证初始化、登录和接口就绪。首次失败没有独立捕获到具体进程竞态，因此不把它断言为已证明的唯一原因；调整后两次实际主控与 Tunnel 安装成功。下载、版本、服务、主控初始化及 Tunnel 就绪失败分别显示脱敏的具体阶段，不输出凭据或原始敏感日志。

`sshd -T` 的输出行顺序在重启前后有所变化，但 106 条有效指令及重复次数一致。持久性比较按指令集合核对，保留最初按原始字符串比较得到的差异证据。

本轮保留已经提交的测试部署和新的独立归档供维护使用。重装前的旧归档没有被覆盖；连接材料、私有计划、完整页面、事务、重启和联网证据只保存在私人测试目录。不得将原归档未改变理解为重装后旧访问材料仍然可用。

## 回归与尚未完成的边界

新增 DNS 出口绑定、已回滚计时器清理、无所有者恢复、拒绝未知任务和脱敏失败阶段行为回归。共享 .NET 核心与工作流 499 项断言通过；DNS 包装程序 5 项、远端事务 25 项、范围恢复 10 项 Python/Bash 行为检查通过。最终完整 `ValidateProject` 通过，主回归 823 项断言及 318 个文本文件的敏感材料扫描通过。Windows 本地一项符号链接测试因权限跳过，Unix CI 执行该检查。安装与更新代码未改变，继续使用 CI 的单次隔离安装生命周期检查。

窗口居中、位置大小记忆及节点按拖动项中心越过相邻行中心即时排序的修正已在 [v0.9.11](TESTING-0.9.11.zh-CN.md)完成；本轮没有改动这些界面代码。两台 IPv4 Debian 12 新机的结果保留在 [v0.9.12](TESTING-0.9.12.zh-CN.md)，不与本轮重复计数。

以下项目没有作为本轮通过项：

- 本机原生直连 IPv6；纯 IPv6-only 主机完整安装与恢复。双栈主机强制 Tunnel IPv6 只证明该连接路径。
- 首次完整部署在每个写入阶段的取消、崩溃和丢失提交确认组合穷举。本轮实测监控追加的中断与计时器回滚，不代表所有首次部署阶段。
- Cloudflare 签发端新旧 Token 的发行、吊销和轮换；旧版 Komari 数据库迁移，需要专属材料和兼容旧样本。
- 实体鼠标捕获、触控、托盘菜单点击、UAC、系统选择器和多物理显示器。

正式包按新的干净提交、版本和实际发布附件核对，不能用候选包或历史发行结果代替。
