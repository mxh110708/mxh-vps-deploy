# 追加安装、部署过程与配置设计

v0.9.8 支持已部署实例多选追加安装，并在执行时显示完整步骤。v0.9.10 补齐 Tunnel 先连接、后配置路由和验证公开访问的流程。

## 在原实例追加安装

新机部署完成或已有 VPS 接入后，进入“实例”，选择目标实例：

| 入口 | 新增内容 | 准备信息 |
|---|---|---|
| 添加协议 | 未安装的 Reality、AnyTLS / ECH、Shadowsocks | 新端口及协议参数 |
| 安装 Agent | Komari 指标采集客户端 | 主控完整地址，执行时输入该节点的 Agent Token |
| 安装主控 | Komari 网页面板与本机数据存储 | 本机监听端口，执行时设置管理员密码 |
| 安装 Tunnel | Cloudflare Tunnel 连接器 | 先在 Cloudflare 建立专属 Tunnel，执行时输入连接 Token；连接成功后再填写公开路由 |

“部署 → 已有实例追加安装”选择同一实例后，可勾选多个组件，统一填写各组件参数并审阅。本轮只建立一个恢复快照、一个任务，安装顺序为所选代理协议、主控、Tunnel、Agent，最后统一验收与提交。已经安装的组件显示状态并禁止勾选；历史状态未核验的组件先进行只读健康检查。“实例 → 添加协议”同样支持同时选择多个未安装协议；监控的独立安装按钮仍可快捷安装单项。

例如原实例已有 Reality：添加 AnyTLS 时填写服务器名称、ECH public name、证书区域、联系邮件和私人 DNS Token 文件，使用不同于 Reality 主、备用监听的端口。原 Reality 继续运行，配置、凭据和默认入口保留。也可以分别追加 SS 或监控组件，无需重新填写实例、重新部署系统或调整管理 SSH。

追加 Reality 当前使用外部 TLS 目标，并在安装前审计。追加 SS 要填写可信入口 IP；防火墙只放行这些入口的 TCP / UDP。AnyTLS 采用 DNS 验证证书；现有证书和 DNS 凭据保留。启用第二个 IPv6 SS 用户时明确填写 IPv6 源地址。

主控默认仅监听本机回环地址，通过 SSH 转发或 Tunnel 访问；管理员用户名为 `admin`，密码在执行时设置，安装阶段验证实际登录。Agent、主控和 Tunnel 各有安装与维护入口；Cloudflare 上的 Tunnel、域名路由和 Access 规则由使用者配置。

Tunnel 的公开网址可以先留空。先安装连接器并等待连接成功，再在“实例 → 完成 Tunnel 公开访问”按页面提示配置 Cloudflare 的“已发布的应用程序”路由：使用页面显示的主机名、本机 HTTP 服务 URL，路径留空，公开访问网址使用 HTTPS。尚未安装本机主控时先追加主控，连接器可以保留。

保存路由后点击“验证公开访问”。应用从 VPS 只读检查连接器就绪、本机主控和公开 HTTPS 接口，并比较版本；通过后保存验证时间与网址。DNS、TLS、HTTP 拒绝、超时及错误接口分别显示原因，HTTP 拒绝包含状态码。检查失败保留先前正确网址，修改路由后可重新验证，无需重装；版本相同不等于验证了主控唯一身份，管理员登录与节点上报需进一步核对。

同时追加主控、Tunnel 和 Agent 时，应用先安装主控与连接器，再显示“准备 Agent 连接”指引。此时可配置路由、打开主控登录并创建节点，取得该节点的 Agent Token 后继续；如 Agent 使用另一主控，则从该主控取得专属节点 Token。取消指引会恢复本轮新增组件。

执行前核对远端状态与归档一致、组件确实未安装、端口空闲；远端残留、未知布局、链接或冲突均停止，避免覆盖。受管防火墙只追加必要规则；保留既有防火墙的实例由使用者先放行新端口。服务商安全组仍由使用者管理。

备份包含本轮所有所选组件，AnyTLS 额外保护证书、凭据和续期设置，受管代理协议安装额外保护防火墙。本轮协议规则一次增量更新，并保留既有规则。提交前比较本轮未选组件的程序、配置、服务定义及启停状态；任一项失败或取消时恢复整轮新增内容，包括此前已安装成功的项。连接丢失或回滚未确认时保留事务，先核对实际状态，不自动重放。待恢复事务未处理时不能追加安装。

## 执行过程直接展示

审阅并执行后，当前主页面变为步骤表，显示计划、状态、耗时和当前操作。新机与追加安装显示各自的实际步骤；按照所选用途展示证书、协议、监控和验收项。

步骤仅在实际操作和状态写入成功后显示“已完成”；正在执行的步骤标为“正在进行”，后续为“待完成”。失败与取消单独标记，不将剩余步骤视为完成。任务期间仍可滚动计划，取消在安全边界处理。结果保留到返回实例或切换页面，不增加独立进度入口或进度弹窗。

## 节点排序与导出提示

在配置设计“节点”步骤，按住左侧手柄上下拖动，上、下半行决定插入位置；整行预览随拖动位置移动，并显示序号、落点线和行高亮，靠近页面边缘自动滚动。v0.9.10 扩大手柄命中区域并统一原生路由事件处理，放置后保留滚动位置。上下按钮和方向键继续可用。点击手柄、Esc 或取消拖动不改变顺序；节点对象和连接关系保留，保存方案和生成配置沿用节点顺序，重排使旧候选失效。后台回归覆盖共用处理器，实际系统指针捕获与物理拖动体验仍需单独验收。

“生成与导出”页始终说明操作顺序：生成配置、校验配置、校验通过后审阅并导出。未生成、待校验、校验失败、缺少导出位置分别显示下一步。所有所选目标通过核心校验并填写导出文件位置后，审阅按钮才可用；输入或浏览选择文件位置会刷新提示。

## 关闭窗口与托盘

“设置 → 关闭设置”提供两个互斥选项：“最小到托盘”和“关闭应用”，选择自动保存，默认直接关闭。最小到托盘保留未保存方案和运行中任务；托盘中可打开应用或退出。直接关闭或托盘退出会先处理未保存方案、在安全边界结束任务。创建托盘图标失败时保留窗口，避免应用无法找回。

## 验证范围

共享核心回归覆盖六类组件的追加、连接与网络保留、端口冲突、失败及取消回滚、步骤完成事件、节点顺序和导出状态。Bash 隔离测试验证独立端口共存、已有服务保留、范围恢复及新 Token 文件轮换。原生 WinUI 验证深浅页面、实际安装表单、步骤状态与导出字段刷新。固定官方 Komari 程序在本机回环地址完成真实初始化和管理员登录。

v0.9.8 使用 B 方案在获授权的 YUNYOO 专用测试机完成 SS 与主控的组合追加、第二项取消后整轮恢复、真实代理连接和本轮清理，保留原 Reality 与管理连接。完整证据范围见[v0.9.8 实测记录](TESTING-0.9.8.zh-CN.md)。

真实证书签发与专用公网 Tunnel 路由缺少本轮材料，明确标记未测。拖动验证了应用内按下、移动与释放路径、插入反馈、重排结果和界面渲染，实际鼠标捕获与拖动体验仍需 Windows 实测。普通应用更新与安装方式保持现有行为，本次未重复应用发现、下载、校验新版的完整链路。
