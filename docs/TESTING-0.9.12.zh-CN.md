# v0.9.12 空白系统部署与重启实测

2026 年 10 月 10 日，用户在服务商面板重装两台专用测试机为 Debian 12 amd64。使用新的隔离私人归档和 [B 方案应用内接口](BACKGROUND-TESTING.zh-CN.md)，通过真实 WinUI 表单、计划审阅、凭据输入、身份确认与任务协调器执行。没有导入旧实例来代替首次部署，没有修改非测试 VPS、系统代理或 TUN。

重装后的 SSH 主机密钥与旧记录不同。用户明确接受本轮取得的两台新身份，随后所有 SSH 检查固定匹配该身份；首次接纳没有记作服务商控制台独立核验。原始密码、密钥与旧归档保留，测试材料按当前用户权限隔离保存。

## 修正与范围检查

原后台测试会话在启动时只列明初始 SSH 端口，而新机计划会生成主、救援管理端口。继续执行会在后续管理入口验收时被测试范围保护阻止。

增加显式的 `AllowManagementPortTransition` 会话选项，默认关闭。正常审阅确认后，仅为会话最初已列明的同一初始 SSH 目标增加计划的两个管理端口。授权证据保存在私人测试目录；其他主机、未列明初始端口、无关端口和派生授权仍拒绝。此选项没有配置云安全组，也没有跳过 SSH 身份或真实访问检查。

30 项后台会话边界断言通过，检查默认拒绝、无效端口、错误主机与初始端口、拒绝后范围不变、正确端口放行、无关端口拒绝及派生授权拒绝。另通过真实原生窗口验证取消审阅不增加端口，默认会话在远端执行和凭据提示前拒绝未授权计划，没有创建部署状态。完整共享核心回归为 477 项断言通过。

## 两台真实新机流程

| 项目 | 结果 |
|---|---|
| 初始系统 | 两台确认空白 Debian 12 amd64，受管代理和监控服务不存在；原服务商认证可用 |
| 原生计划审阅 | 两台选择 Reality 与 Shadowsocks，显示对象、用途、端口、改动与执行顺序，确认后才开始 |
| 云侧端口可达 | 仅在所审阅管理端口短暂监听随机标记，从本机验证 TCP；随后关闭临时监听，没有改防火墙或服务 |
| 管理访问 | 管理密钥、本地权限、基线备份、root 密钥登录与 admin 密码 sudo 通过；两个管理端口分别验证 |
| MOE 初始低端口迁移 | 新主、救援入口和协议验收成功后，经正常确认流程移除初始入口；有效 SSH 配置只保留双管理入口 |
| YUNYOO 原高位入口 | 保留原高位端口为主入口，另建立救援入口；两套 root/admin 管理访问均通过 |
| 实际协议安装 | Reality 主入口、备用入口与 Shadowsocks 安装、共存、服务监听和防火墙检查通过；网络调优按现有手动策略跳过 |
| 提交前客户端验收 | 每台分别使用固定 sing-box 与 Mihomo，验证三项入口的真实 HTTPS、出口地址及 UDP，每台 6 项全部通过，无用户跳过 |
| 部署提交 | 两台部署事务均为 `Committed`，归档与导出完成，没有未确认事务所有者 |
| 真实重启 | 两台实际启动身份变化；重启后各完成 4 次 root/admin 密钥与 sudo 检查，服务启用且运行、防火墙配置有效 |
| 重启后配置持久性 | 两台所检查受管配置文件的 SHA-256 与权限均与重启前一致，有效 SSH 端口与认证策略一致 |
| 重启后客户端验收 | 再次使用固定双核心，各 6 项 HTTPS、出口和 UDP 检查全部通过，共 12 项；回环测试核心均退出 |
| 应用内健康检查 | 重启后经两台原生实例维护界面运行健康审计，均完成 |
| 原归档与前台保护 | 两台原始私人归档各 17 个文件摘要不变；原生窗口激活和前台采样均为零，没有注入全局输入 |

本轮验证首次安装和重启后持久性，保留两台已经提交的测试部署及其新的独立归档，供后续维护与恢复检查。原始旧归档没有被替换；重装后的部署身份与访问材料应使用本轮新归档。原始页面、事务、重启前后与联网证据保存为私人材料，公开报告省略具体连接及凭据信息。

## 已有覆盖和剩余条件

之前在已有实例完成的 AnyTLS/ECH 证书申请与续期、监控三组件组合安装、Tunnel 连接后路由配置、Agent 上报、协议共存切换、跨版本升级、凭据轮换、选定范围恢复及应用意外退出恢复，见 [v0.9.11](TESTING-0.9.11.zh-CN.md)及其关联报告。这些没有作为本轮空白系统流程重新计数。

重装前还在 MOE 完成 SS 追加、取消回滚、Xray 跨版本升级与恢复原版本，以及主控安装后的应用意外退出和按范围回滚。只读借用已有 IPv6 VPS 完成真实客户端链路、SS IPv6 第二用户出口和 UDP 检查，未修改非测试节点。两台新系统均没有可用全局 IPv6，因此新装 IPv6 第二用户、IPv6 防火墙迁移与 IPv6-only Tunnel 仍缺可修改的 IPv6 测试环境。

首次完整部署在各个写入阶段的取消、崩溃与丢失提交确认组合没有穷举，本轮实际执行的是正常新机提交及重启路径。Cloudflare 签发端发行、吊销新旧 Token 需要专属材料；旧版 Komari 数据库迁移需要一致的兼容旧数据样本。实体鼠标捕获、托盘菜单点击、系统选择器、UAC、触控和多物理显示器仍需单独验收。

安装和更新代码没有改变，保留现有 CI 的单次隔离安装生命周期检查；新发行包需按正式版本与实际附件核对，不能用历史发行的结果代替。
