# v0.9.11 窗口启动、节点拖动与补充实测

2026 年 10 月 9–10 日，在用户授权的 YUNYOO 专用测试机和隔离私人归档中补充实测。使用 [B 方案应用内接口](BACKGROUND-TESTING.zh-CN.md)驱动真实 WinUI 控件与运维流程；测试窗口保持屏幕外，不注入全局鼠标或键盘，不改变系统代理或 TUN。

## 窗口启动

默认以标准逻辑尺寸在主屏幕工作区中央打开，小屏幕按可用空间缩小。“设置 → 窗口启动”可开启关闭时位置和大小记忆，默认关闭；取消后清除旧位置。保存正常窗口位置，按目标屏幕 DPI 恢复；工作区变化时限制到可见区域，原显示器不可用或存档无效时回到默认居中。

实际创建未显示的原生窗口，经系统关闭消息保存其位置和大小，并核对磁盘设置；屏幕外测试主窗口不得覆盖保存位置。另核对窗口记忆与自动更新两个开关独立保存。随后真实重启应用，验证记忆恢复、关闭记忆而存在旧数据、模拟原显示器不可用、屏幕外位置限制和坏配置回退。每次核对显示前的实际窗口边界，测试窗口随后隔离到屏幕外；激活和前台采样均为 0。共享核心检查负显示器原点、DPI、较小工作区、反复恢复无位移和非法配置边界。

实现核对了微软对 [每窗口 DPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow) 和 [正常窗口位置坐标](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement) 的说明。工作区与屏幕坐标仅转换一次，避免任务栏位于顶部或左侧时累积偏移。当前机器实际验证了 150% 缩放；其他物理显示器组合仍需单独检查。

## 节点拖动

修正前在原生窗口复现了普通相邻交换失败。旧算法比较鼠标与目标行中心，但整行预览根据按下位置偏移，两者阈值不同；靠近手柄下方按下时需额外上拖。

现在以预览行中心选择最近的位置。相邻行之间移动超过约半行即可出现交换提示，手柄按下位置不改变阈值；恰好在中间界线时保持原位置。指针、目标行和预览通过实际 XAML 变换转换到滚动视口，覆盖层位置不假定与页面原点相同。

原生回归覆盖手柄上、中、下按下位置、上下相邻交换、临界前后与准确界线、深浅主题、紧凑窗口、长列表边缘滚动、取消与失去捕获、点击不排序、列表外释放、旧页面与其他指针拒绝、键盘首尾边界、滚动位置保留，以及保存、生成、双核心校验与两份配置导出。记录实际几何与渲染图像；等待真实 ScrollViewer 位置和呈现完成后测量。

后台接口调用与原生路由事件相同的处理器，没有制造物理鼠标事件。系统指针捕获、多显示器、触控和用户实体鼠标体验仍需单独验收。

| 两种协议组合追加 | 一次追加 AnyTLS/ECH 与 Shadowsocks，独立端口与原 Reality 共存；本轮新增服务按范围提交，真实客户端 8 项 HTTPS、出口和 UDP 检查全部通过，没有选择跳过 |
| 代理核心升级 | AnyTLS/ECH 与 Shadowsocks 分别从 sing-box 1.14.1 升到 1.14.2，两次均通过真实客户端 8 项检查并提交；Reality 另通过 Xray 同版本升级流程和 6 项连接检查 |
| 入口切换与共存 | 通过正常界面切到 AnyTLS，再切回 Reality；分别通过 4 项与 6 项连接检查。再次启用 AnyTLS 共存后，8 项检查全部通过 |
| 凭据轮换与备份恢复 | Reality、AnyTLS/ECH、Shadowsocks 分别通过凭据轮换和 8 项连接检查；从轮换前备份仅恢复协议配置，再通过 8 项连接检查并提交，监控范围未被覆盖 |
| 实测组件清理 | 经正常界面移除两种新增协议与 Agent，核对剩余协议连接；按初始不存在证明与文件身份清理本轮主控、Tunnel、连接凭据及证书。原 Reality、防火墙、两个 SSH 管理入口和正式归档核对通过 |
| 意外退出恢复 | 在主控与 Tunnel 已真实连接、准备 Agent 的节点，仅终止自有测试应用进程。实际重启后识别未完成事务并禁用删除实例；经正常界面明确核对恢复，同一任务的三组件事务确认 `RolledBack`。新增服务和 Agent 文件不存在，原配置摘要、健康检查、两个 SSH 入口及正式归档核对通过 |

为验证跨版本升级，只在独立测试归档中临时固定官方 [sing-box 1.14.1](https://github.com/SagerNet/sing-box/releases/tag/v1.14.1) 的 amd64 安装资产及官方 SHA-256，安装到本轮新增的两项服务；客户端验证核心仍使用原固定版本。正式支持目录保持 1.14.2，不更改正式归档或其他 VPS。

Shadowsocks 首次轮换在真实客户端 8 项检查通过后，验收阶段重连 SSH 超时，事务已确认回滚。独立检查确认原服务可用；未证实超时的底层原因。确认旧事务结束后，通过界面重新审阅的新任务完成轮换与全部连接检查，没有重放未确认的写入，也没有跳过验收。

收尾核对正式实例归档的 17 个文件数量与摘要、源 Tunnel Token 文件摘要，以及两个管理入口的实际 SSH 认证。清理范围限于本轮新增服务、监听与敏感配置；共享系统工具和历史恢复备份保留，未删除既有恢复材料。

原始界面、事务、真实连接与清理证明保存在本地私人测试目录。公开报告省略测试地址、端口、域名、邮箱、账号、Token 和密钥。

## 本地验证与边界

项目主回归和 467 项共享核心断言通过。原生界面回归覆盖窗口设置、组合安装、维护入口与节点拖动，另核对五种实际重启情形；已完成的正常界面流程包括配置保存、生成、校验与导出。窗口激活次数和前台采样均为 0。

全新空白系统部署需重装系统后单独测试；当前测试始于既有 Reality 实例。测试机没有可用的 IPv6 服务配置，未覆盖纯 IPv6 SS 第二用户与 Tunnel。Cloudflare 签发端的新 Token 发行、吊销旧 Token 需新的凭据；没有在账户控制台轮换或吊销。旧版主控数据库迁移需兼容的旧数据样本。本轮补测实际恢复路径，不代表所有断网、崩溃时点和丢失提交确认组合均已覆盖。

系统托盘菜单点击、滚轮、系统文件选择器、UAC 与多显示器仍受“不操控桌面、不抢鼠标”限制。安装更新代码未变；保留 CI 的单次隔离安装、更新、重启与卸载检查，并核对最终提交和正式发行附件；未将隔离安装测试当成当前公开版本的完整在线更新体验。

已有结果与边界见 [v0.9.10](TESTING-0.9.10.zh-CN.md)、[v0.9.9](TESTING-0.9.9.zh-CN.md)、[v0.9.8](TESTING-0.9.8.zh-CN.md)和 [v0.9.7](TESTING-0.9.7.zh-CN.md)。
